# Единый конвейер импорта

## Назначение

`UnifiedImportService` предоставляет единый application-контракт для пяти источников: `sales`, `market`, `promo`, `tv`, `visits`. UI должен выбирать тип источника и передавать уже разобранные строки; UI не обращается к IndexedDB напрямую.

## Контракт

- Вход: `projectId`, `sourceType`, `rows`, необязательный `sourceBatchId`.
- Выход: число импортированных и пропущенных строк, список диагностик, версия набора, fingerprint, проект, источник и время завершения.
- Ошибка нормализации или сохранения пробрасывается вызывающему коду; успешный результат не формируется.
- Пустой проект и пустой набор отклоняются до вызова хранилища.

## Границы атомарности

Каждый нормализатор атомарно публикует свой источник вместе с версией и инвалидацией агрегатов. Пакет из нескольких источников не является общей транзакцией: каждый источник публикуется отдельно. Если нужен all-or-nothing импорт комплекта файлов, потребуется staging-слой и отдельная транзакция публикации после проверки всех пяти источников.

## Следующий этап

1. Подключить единый сервис к экрану импорта и добавить явный выбор источника.
2. Хранить статус партии импорта (`preview`, `committing`, `committed`, `failed`) в `importBatches`.
3. Добавить staging, чтобы несколько файлов можно было проверить до публикации.
4. Запустить тесты в поддерживаемых браузерах, включая quota errors, закрытие вкладки и повторный импорт.
