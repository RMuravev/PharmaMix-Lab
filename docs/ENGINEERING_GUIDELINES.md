# Engineering guidelines

1. Компоненты отображения не выполняют бизнес-расчёты и не обращаются к IndexedDB.
2. Каждая страница использует собственный query service и общие UI-примитивы; повторяемые KPI, фильтры, таблицы и графики оформляются в `shared/ui`.
3. Алгоритмы принимают входные данные и параметры явно; результат должен быть детерминированным при одинаковых входах, если случайность не является частью модели.
4. Все вычисления, способные блокировать UI, выполняются в Web Worker; Worker-протокол содержит task ID, типизированный success/error/progress, версию данных и алгоритма.
5. Ошибки не маскируются пустыми массивами/успешными статусами. Ошибка импорта должна оставить предыдущий рабочий набор данных нетронутым.
6. Инвалидация агрегатов должна быть явной и привязана к изменившемуся набору/алгоритму. Не использовать эвристические cache keys на основе количества строк и суммы продаж.
7. Единицы измерения, форматирование, палитра графиков и семантика цветов определяются централизованно.
8. Для изменения математической логики сначала фиксируется golden test; далее изменение проходит сравнение старого и нового расчёта с согласованными допусками.
9. Каждая новая возможность сопровождается unit-тестом; импорт, миграции, workers и сохранение результатов — интеграционными тестами.
10. Не удалять legacy-модуль, пока его потребители не перенесены и результаты не прошли регрессионное сравнение.
